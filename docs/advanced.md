# Расширенные настройки и возможности

Страница для тех, кому нужно настроить CSQTT подробнее. Базовые шаги — в README,
назначение страниц панели — в документе [«Панель LuCI»](luci.md).

## Что умеет CSQTT

- Хранить **несколько сохранённых серверов** и переключаться между ними:
  автоматический выбор по приоритету, переключение на резервный сервер при сбое
  (failover), возврат обратно (failback), пауза перед повторной попыткой (cooldown) и
  повторные подключения.
- Проверять подключение (health-check) по `transport` / `data` / `both`, с порогами и
  интервалом проверки.
- Авторизоваться в VK в трёх режимах: `vkcalls` (VK-хеши и ссылки `vk.com/call/join`),
  `auto_js` (по токену доступа VK) и `auto_api` (ядро само создаёт звонки VK по токену,
  хеши не нужны).
- Задавать число воркеров `9..126` (кратно 9), обфускацию `audio` / `video` и транспорт
  TURN `udp` / `tcp_tls`.
- Проходить CAPTCHA: встроенный решатель и локальная страница прохождения CAPTCHA для
  телефона в той же сети (Web Helper).
- **Проверять доступ через `csqtt0`**: активная проверка выбранной цели строго через
  интерфейс туннеля (без скрытого выхода через WAN), TLS с проверкой сертификата и имени
  хоста; результат привязан к текущей сессии, есть кнопка ручного повтора и честные
  состояния («Проверяется / Доступ подтверждён / Проверка не прошла / Результат устарел»).
- **Показывать состояние каждого VK-хеша**: «проверен / недействителен / нужна CAPTCHA /
  недоступен / не проверялся / не используется». «Не используется» **не** значит
  «сломан», а общее состояние туннеля не выдаётся за проверку всех хешей. Кнопка
  **«Проверить хеши»** повторяет проверку без переподключения.

Секреты (`password`, `vk_js_token`) — write-only: в интерфейс, статус и логи не
выводятся. Пустое секретное поле при сохранении сохраняет прежнее значение.

> Стабильность зависит от сети, сервера и настроек. Проект не гарантирует бесперебойную
> работу и не является средством обхода законодательства.

## Режимы авторизации VK

Настраиваются на странице **«Туннель и VK»** — это **общие** настройки для всех серверов
(в редакторе профиля их нет).

| Режим | Что нужно | Когда применять |
|---|---|---|
| `vkcalls` (по умолчанию) | VK-хеши или ссылки `vk.com/call/join` | ссылка подключения содержит хеши |
| `auto_js` | токен доступа VK | ссылка без хешей |
| `auto_api` | токен доступа VK | ссылка без хешей; звонки создаёт само ядро |

Поля панели: **«Режим авторизации VK»**, **«Получение хешей VK»**, **«Токен доступа VK»**,
**«Хеши / ссылки VK»**.

### Ссылка CSQTT и VK-токен — это разные вещи

- **Ссылка подключения `csqtt://…`** содержит адрес сервера, порт и пароль (и, в форме
  v2, возможно, список VK-хешей). Её выдаёт владелец сервера.
- **Токен доступа VK** нужен только для `auto_js` / `auto_api`. Это отдельный секрет VK,
  а не часть ссылки. В LuCI у него отдельное поле **«Токен доступа VK»**.

Не вставляйте токен в поле ссылки и наоборот.

## Токен доступа VK

Подходит **implicit-flow** (VK OAuth) для приложения с доступом к звонкам. Например, через
сервис `https://vkhost.github.io/`: выберите приложение, разрешите доступ и скопируйте из
адресной строки часть **от `access_token=` до `&expires_in`**. Инструкция внешнего сервиса
может меняться — проверяйте её актуальность на самом сервисе.

Поле **«Токен доступа VK»** принимает оба варианта:

- сам токен (обычно начинается с `vk1.`);
- **полный redirect-URL** целиком, например
  `https://oauth.vk.ru/blank.html#access_token=vk1.a…&expires_in=…&user_id=…`.

LuCI и служба сами извлекут параметр `access_token`/`token`, декодируют URL-кодирование и
уберут пробелы по краям. Если вставить произвольный текст, который не является токеном,
LuCI сообщит об ошибке, а клиент не станет отправлять его на сервер.

> **Токен и полный OAuth redirect-URL — это секреты.** Не публикуйте их, не пересылайте в
> мессенджерах и не вставляйте в тикеты. При подозрении на утечку отзовите токен и
> получите новый.

## Команды на роутере

```sh
csqtt status             # активный профиль, состояние, счётчики
csqtt status --json      # то же машинно-читаемо
csqtt doctor             # read-only диагностика (конфиг, TUN, peer, rp_filter)
csqtt doctor --json      # диагностика машинно-читаемо
csqtt log tail -n 50 -f  # журнал с маскировкой секретов
uci show csqtt           # текущая конфигурация
```

## Конфигурация UCI

Конфигурация хранится в `/etc/config/csqtt`. Изменения применяются командой
`/etc/init.d/csqtt restart` (или перезапуском службы в панели).

Секция `main`:

| Ключ | Значения | Смысл |
|---|---|---|
| `enabled` | `0` / `1` | служба включена |
| `ifname` | `csqtt0` | имя интерфейса туннеля (фиксировано) |
| `selection_mode` | `priority` / `manual` | как выбирается сервер |
| `active_profile` | id секции | активный профиль в режиме `manual` |
| `failover` / `failback` | `0` / `1` | переключение на резервный сервер и возврат |
| `health_interval` | секунды | интервал проверки подключения |
| `health_mode` | `transport` / `data` / `both` | что проверяет health-check |
| `health_target` | адрес | цель проверки (пусто — по умолчанию) |
| `fail_threshold` / `success_threshold` | число | пороги переключения |
| `cooldown` | секунды | пауза перед повторной попыткой |
| `reconnect_delay` | секунды | пауза перед повторным подключением |
| `failback_stable_time` | секунды | сколько держится связь до возврата |
| `tun_mtu` | число | MTU интерфейса `csqtt0` |

Секция `routing.mode`: `auto` — **interface-only** (служба не ставит маршруты, правила и
таблицы, системный DNS не меняет); `none` — отладочный алиас. Других режимов нет.

Профиль — секция `config server <id>`: `name`, `enabled`, `priority` (меньше — выше),
`peer` (`host:port`), `password`, `vk` (хеши через запятую), `device_id`, `workers`
(`9..126`, кратно 9), `obfs` (`audio` / `video`), `turn_transport` (`udp` / `tcp_tls`),
`fingerprint`. Автозапуск: пакет регистрирует и включает init-скрипт при установке, но
туннель не поднимается, пока `main.enabled='0'`. Отключить автозапуск —
`/etc/init.d/csqtt disable`.

Добавлять профили удобнее из панели (**«Профили» → «Импортировать ссылку»**) или командой
`csqtt profile import 'csqtt://…' --commit`.
