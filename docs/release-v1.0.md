# Выпуск CSQTT OpenWrt v1.0

Новый публичный выпуск репозитория **CSQTT OpenWrt** (`github.com/starkugz/csqtt-openwrt`).

Тег `v1.0` — это имя **публикации** репозитория, а не версия пакета. В этом выпуске
нумерация пакетов начинается заново: `csqtt` и панель — `1.0`, ядро сохраняет базовый
upstream-номер `2.1.9`. Номера пакетов **меньше**, чем в `v1.1.0`/`v1.1.1` (`csqtt`
`1.1.0-r2`, панель `1.1.1-r1`), поэтому для уже установленной системы обновление — это
**понижение версии**. Установщик сравнивает версии **пакетов** из `MANIFEST.txt` (не имена
тегов) и выполняет замену принудительно: `opkg` — с `--force-downgrade` (без флага `opkg`
печатает `Not downgrading package …` и молча ничего не меняет), `apk` понижает по явно
указанному файлу сам. После установки установщик проверяет, что версия действительно
заменилась. Настройки, профили, пароли, токены, VK-хеши и `device_id` при этом сохраняются.

## Версии

| Компонент | Версия в v1.0 |
|---|---|
| Ядро CSQTT (`csqtt-core`) | **2.1.9** — базовый upstream-номер; сборка содержит локальные исправления и не совпадает с официальным `2.1.9` побайтово |
| Интеграционный пакет для OpenWrt (`csqtt`) | **1.0-r2** |
| Панель LuCI (`luci-app-csqtt`) | **1.0-r1** — русский интерфейс **встроен** |
| Отдельный пакет перевода (`luci-i18n-csqtt-ru`) | **не публикуется**: перевод встроен в панель |

Версии независимы и не выравниваются между собой: ядро сохраняет upstream-номер `2.1.9`,
пакет интеграции и панель — свои (`1.0-r2` и `1.0-r1`). Суффикса локальной редакции ядра
(`-csqtt.N`) больше нет. Версия ядра отображается на странице **«О программе»** в LuCI
(`csqtt version`
на роутере).

## Что изменилось

Выпуск закрывает исправления, найденные при **живой проверке на роутере** (2026-10-15), когда
панель или `doctor` сообщали **недостоверное** состояние. Относительно опубликованного v1.1.1
(пакет `1.1.0-r2`, панель `1.1.1-r1`) изменения такие:

- **D1–D6 — достоверность состояний и удаление.** Контракт счётчиков трафика и достоверность
  признака «трафик действительно идёт»; классификация FakeIP в активной проверке доступа;
  единый источник активного профиля (профиль показывается по факту работы, а не по настройке);
  честное состояние Web Helper (включён / включён, но не слушает / не отвечает);
  обработка ошибок `stop`/`disable` при удалении и корректный код возврата.
- **F1 — Web Helper не поднимался, если адрес LAN записан списком.** На проверенном устройстве
  адрес секции `lan` записан как `list ipaddr '192.168.1.1/24'`; прежний разбор понимал только
  `option ipaddr`. Хелпер молча не открывался, а панель сообщала «выключен в настройках» —
  **ложный диагноз**. Теперь понимаются оба варианта записи.
- **F2 — Web Helper мог слушать частный адрес WAN.** Теперь сетевой адрес слушателя разрешён
  только из набора адресов секции `lan`; частный адрес WAN права слушать не даёт; `0.0.0.0`,
  публичные адреса, link-local, CGNAT и ULA вне LAN отклоняются; loopback API работает отдельно.
  Если LAN-адрес определить не удалось, сетевой bind отклоняется с понятной причиной.
- **F4 — `doctor` больше не даёт ложный диагноз.** Основной признак доступности сервера — это
  состояние сессии из `status.json`, а не ответ на одиночную UDP-пробу через WAN (сервер штатно
  молчит на такую дату). Молчание пробы при работающей сессии больше не даёт `[WARN]`.
  При этом **устаревший** `status.json` (служба не пишет) не считается доказательством
  работающей сессии: `doctor` честно сообщает «состояние сессии неизвестно».
- **F5 — «залипание» прежнего профиля после смены выбора.** При переключении профиля
  (ручной выбор в панели или возврат к выбору по приоритету) прежний активный профиль
  сохранял состояние `active`, и панель показывала **два** профиля как «Подключено», хотя
  туннель один. Теперь профиль, освободивший активный слот, возвращается в `standby`:
  контракт «активный ровно один» соблюдается, а резервный профиль снова доступен для
  выбора. Исправление в ядре — релиз интеграционного пакета поднят `1.0-r1 → 1.0-r2`
  (панель не менялась, остаётся `1.0-r1`). Заодно в команды установки и обновления
  (README, `docs/install.md`, `docs/update.md`) добавлен перезапуск службы после успешной
  установки: менеджер пакетов не перезапускает уже работающий процесс, поэтому без
  перезапуска обновление не вступало в силу — продолжало работать прежнее ядро из памяти.

## Установка и обновление

Установка на роутер — по инструкции в
[README](https://github.com/starkugz/csqtt-openwrt/blob/main/README.md#установка-на-роутер).
Ручная установка пакетами — в [«Установка на роутер»](install.md).

В README собраны **четыре короткие копируемые команды** с официального адреса
`raw.githubusercontent.com/starkugz/csqtt-openwrt/main/…`:
[«Быстрые команды»](https://github.com/starkugz/csqtt-openwrt#быстрые-команды-установка-и-удаление).

- **на роутере по SSH** — установка/обновление клиента и панели (`install-csqtt.sh`) и
  удаление (`uninstall-csqtt.sh`); файл скачивается целиком и запускается только после
  успешной загрузки, затем служба перезапускается;
- **на VPS по SSH** — установка и удаление серверной части. Команда скачивает **загрузчик**
  `install-server-online.sh`: он сам проверяет `curl`/`wget` и `python3`, скачивает
  `install-server.sh` вместе с `server/serverctl.py` и `server/source-lock.json` во временный
  каталог, запускает штатный установщик с переданными аргументами и убирает за собой (режим
  удаления — тот же загрузчик с аргументом `uninstall`).

**Обновление сохраняет** настройки, профили, пароли, токены, VK-хеши и `device_id` —
и с v1.1.0, и с v1.1.1. Номера пакетов в `v1.0` меньше, чем в прежних выпусках, поэтому
замена выполняется как **принудительное понижение версии** (см. «Версии» выше);
подробности и ручные команды — в [«Обновление и удаление»](update.md).

Удаление — [одним скриптом](update.md#удаление): служба останавливается, автозапуск снимается,
пакеты удаляются, а **настройки сохраняются**. Если настройки больше не нужны, их удаляют
вручную (`rm -f /etc/config/csqtt`) — отдельного режима «удалить с настройками» нет.

## Совместимость и ограничения

- CSQTT работает в режиме **interface-only**: он поднимает интерфейс `csqtt0`, но трафик сам
  не направляет — нужен прокси-клиент, привязанный к `csqtt0` (см.
  [совместимость с прокси-клиентами](compatibility.md)).
- Поддерживаются OpenWrt **25.12.x** и **SNAPSHOT** (пакеты `apk`), **24.10.x** (`ipk`).
  Для SNAPSHOT совместимость заявлена только для зафиксированной ревизии `r36953-0ab51fb9c1`.
- Пакеты не подписаны ключом репозитория OpenWrt — при ручной установке `apk` нужен
  `--allow-untrusted`.
- **Серверная часть не менялась**: выпуск клиентский, совместим с уже работающим сервером
  CSQTT. Инструкции по серверу — в [«Сервер на VPS»](server.md).
- Гарантированная совместимость со всеми устройствами и архитектурами не заявляется.
