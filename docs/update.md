# Обновление и удаление

## Обновление с сохранением данных

Обновление — установкой новых пакетов из Release. Конфигурация
`/etc/config/csqtt`, токены, VK-хеши, пароли и `device_id` сохраняются как
conffile. Панель (`luci-app-csqtt`) собрана как `architecture all`, одинакова для
всех архитектур и **всегда на русском** (начиная с панели `luci-app-csqtt`
`1.1.0-r3` перевод встроен в панель; отдельный `luci-i18n-csqtt-ru` не требуется); между
архитектурами различается только ядро.

**25.12.x / SNAPSHOT (apk):**

```sh
apk add --allow-untrusted \
  ./csqtt-2.1.9-openwrt-25.12-<arch>.apk \
  ./luci-app-csqtt-1.0-openwrt-25.12.apk
/etc/init.d/csqtt restart
```

**24.10.x (opkg):**

```sh
opkg install --force-downgrade \
  ./csqtt-2.1.9-openwrt-24.10-<arch>.ipk \
  ./luci-app-csqtt-1.0-openwrt-24.10.ipk
/etc/init.d/csqtt restart
```

> **Почему `--force-downgrade`.** Номера пакетов этого выпуска (`csqtt` `1.0-r2`,
> панель `1.0-r1`) **меньше**, чем в ранее опубликованных v1.1.0/v1.1.1 (`csqtt`
> `1.1.0-r2`, панель `1.1.1-r1`), поэтому обновление с них — понижение версии.
> `apk` с явно указанным файлом понижает сам, а `opkg` без флага печатает
> `Not downgrading package …` и **ничего не меняет** (при этом завершается
> успешно). Флаг безвреден и для обычного обновления: если понижения нет, он ни
> на что не влияет.

Для совместимости со **старыми** выпусками установщик по-прежнему принимает
отдельный `luci-i18n-csqtt-ru`, если он есть в манифесте, и не требует его
удаления.

Установщик сохраняет `/etc/config/csqtt` (резервная копия с правами только для
root) и состояние включения службы; пакеты при ошибке установки **не удаляются**.
Понижение версии выполняется принудительно (см. выше), и после установки
установщик проверяет, что версия действительно заменилась: если менеджер молча
пропустил замену, установка завершается ошибкой, а не сообщением об успехе.
Резервный переход с удалением пакетов (`CSQTT_ROLLBACK_DIR` или
`/tmp/csqtt-rollback`) остаётся на случай, когда прямая установка не удалась.
Резервная копия одного конфига не заменяет откат пакетов. Перед сменой схемы
версий сделайте резервную копию `/etc/config/csqtt`.

## Обновление только ядра

Ядро (`csqtt`) и панель (`luci-app-csqtt`) — отдельные пакеты. Если нужно
обновить только ядро, не меняя установленную панель, используйте режим «только
ядро»: скачивается и устанавливается лишь пакет ядра, а панель, настройки,
профили, токены, VK-хеши и `device_id` остаются без изменений.

```sh
# автоустановщик: только ядро из выпуска
CSQTT_CORE_ONLY=1 sh install-csqtt.sh
# либо
sh install-csqtt.sh --core-only
```

Если скрипта на роутере ещё нет, скачайте его безопасно и запускайте **только после успешного
скачивания** (обрыв связи не должен приводить к запуску неполного файла):

```sh
wget --no-proxy -qO /tmp/csqtt-install.sh https://raw.githubusercontent.com/starkugz/csqtt-openwrt/main/install-csqtt.sh \
  && ash /tmp/csqtt-install.sh --core-only && /etc/init.d/csqtt restart
```

Обновление ядра **не вступает в силу без перезапуска службы**: менеджер пакетов заменяет
файл, но уже запущенный процесс продолжает работать с прежним бинарником. Перезапуск
(`/etc/init.d/csqtt restart`, как в примере выше и ниже) обязателен после успешной установки.

Вручную это то же самое — установить один пакет ядра:

```sh
apk add --allow-untrusted ./csqtt-2.1.9-openwrt-25.12-<arch>.apk   # 25.12/SNAPSHOT
opkg install --force-downgrade ./csqtt-2.1.9-openwrt-24.10-<arch>.ipk   # 24.10
/etc/init.d/csqtt restart
```

**Совместимость ядра и панели.** Панель и ядро одного выпуска согласованы.
Перед изменениями установщик сравнивает базовую версию установленной панели с
панелью выпуска; при несовпадении он **останавливается до изменений** и
сообщает об этом — совместимость интерфейса ядра и панели не гарантируется.
Вручную оставленную панель можно заменить позже обычным обновлением (без
`CSQTT_CORE_ONLY`). Осознанный обход проверки — `CSQTT_ALLOW_MIXED=1`
(только если вы уверены в совместимости).

## Удаление

Автоматическое удаление — команда **на роутере**. Она скачивает и запускает
[`uninstall-csqtt.sh`](../uninstall-csqtt.sh): скрипт определяет менеджер пакетов (`apk` или
`opkg`), останавливает службу и снимает автозапуск, затем удаляет ядро/интеграцию (`csqtt`)
и панель (`luci-app-csqtt`), а также отдельный `luci-i18n-csqtt-ru`, если он остался от
старых выпусков.

```sh
wget --no-proxy -qO /tmp/csqtt-uninstall.sh https://raw.githubusercontent.com/starkugz/csqtt-openwrt/main/uninstall-csqtt.sh \
  && ash /tmp/csqtt-uninstall.sh
```

Отсутствующие пакеты пропускаются, ошибки удаления не скрываются. Если не удалось
остановить службу (`stop`) или снять автозапуск (`disable`), скрипт **не выдаёт полный
успех**: удаление продолжается, но итог и код возврата ненулевые, а в выводе указано, что
именно не сработало (процесс может продолжать работу, автозапуск может остаться включённым).
Повторный запуск скрипта безопасен. Скрипт просит удалить только свои пакеты
(autoremove/cleanup/`--recursive` не передаются), но **apk** (OpenWrt 25.12+) по
своей семантике `apk del` дополнительно убирает автоматически установленные
зависимости, которые больше никому не нужны: такие зависимости
(`kmod-tun`, `ucode-mod-socket`, `coreutils-timeout`) могут исчезнуть вместе с
CSQTT. Зависимости, установленные в системе явно (в `/etc/apk/world`) или
нужные другим пакетам и базовой системе (`rpcd-mod-ucode`, `luci-base`, `libc`
и т. п.), остаются; **opkg** (24.10) зависимости не трогает вовсе. Конфигурацию,
профили и данные доступа (`/etc/config/csqtt`) скрипт перед удалением копирует в
защищённый временный каталог и восстанавливает, если менеджер пакетов их снёс
(каталог конфигурации при необходимости создаётся заново); если копию создать не
удалось, удаление не начинается. Маршрутизация, DNS, firewall и другие
приложения не изменяются; серверную часть на VPS скрипт не затрагивает.

Ниже — ручной вариант теми же шагами.

```sh
/etc/init.d/csqtt stop
/etc/init.d/csqtt disable
# менеджер: apk (25.12.x/SNAPSHOT) или opkg (24.10.x)
if command -v apk >/dev/null 2>&1; then PM_DEL="apk del"; else PM_DEL="opkg remove"; fi
# пакеты удаляются в порядке зависимостей:
# luci-i18n-csqtt-ru (только legacy-выпуски) зависит от luci-app-csqtt,
# а тот — от csqtt. На новых установках перевода нет — шаг пропускается.
for p in luci-i18n-csqtt-ru luci-app-csqtt csqtt; do
    $PM_DEL "$p"
done
# конфигурация остаётся (conffile); полное удаление:
rm -f /etc/config/csqtt
```

Не забудьте убрать привязку `csqtt0` в пользовательском прокси (Mihomo/ssclash),
иначе его исходящие соединения останутся без интерфейса.
