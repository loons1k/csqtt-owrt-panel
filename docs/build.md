# Сборка, версии и проверки

Технические подробности: какие версии у компонентов, из чего собраны пакеты, что уже
проверено, а что нет.

## Версии компонентов

| Компонент | Версия |
|---|---|
| Встроенное ядро CSQTT (`csqtt-core`) | **2.1.9** — базовый upstream-номер; сборка содержит локальные исправления и не совпадает с официальным `2.1.9` побайтово |
| Интеграционный пакет для OpenWrt (`csqtt`) | **1.0-r2** |
| Панель LuCI (`luci-app-csqtt`) | **1.0-r1** — русский интерфейс **встроен** |
| Отдельный пакет перевода (`luci-i18n-csqtt-ru`) | **не нужен**: панель всегда на русском |

У ядра и пакетов **разные версии**: ядро сохраняет базовый upstream-номер (`2.1.9`) и не
переименовывается в 1.x; версия ядра отображается на странице **«О программе»** в LuCI и не
подменяется версией пакета. **Чем ядро отличается от панели:** ядро (`csqtt`) — это сам
туннель и служба; панель (`luci-app-csqtt`) — только веб-интерфейс LuCI. Панель **всегда на
русском** (перевод встроен в панель), поэтому отдельная русификация не нужна; для ручной
установки достаточно **двух** файлов: ядро и панель.

Версии независимы и искусственно не выравниваются. Выпуск **v1.0** содержит ядро `2.1.9`,
интеграционный пакет `1.0-r2` и панель `1.0-r1`. Тег выпуска (`v1.0`) — это имя
**публикации** репозитория, а не версия пакета. Номера пакетов `v1.0` **меньше**, чем в
`v1.1.0`/`v1.1.1` (`csqtt` `1.1.0-r2`, панель `1.1.1-r1`): для обновления с них установщик
сравнивает версии **пакетов** (не теги) и заменяет пакеты принудительно (`opkg`
`--force-downgrade`; `apk` понижает по явному файлу сам), а затем проверяет, что замена
действительно произошла.

Релиз интеграционного пакета поднят до `1.0-r2`: содержимое **ядра** изменилось (исправление
достоверности состояний профилей, см. [заметки о выпуске](release-v1.0.md)). Панель не
менялась и остаётся `1.0-r1`. Версия пакета сравнивается менеджером пакетов, поэтому без
подъёма релиза исправленное ядро не установилось бы поверх уже установленного `1.0-r1`
(`apk` при совпадающей версии считает пакет уже установленным).

## Из чего собраны пакеты

- **Ядро** — статически слинкованный **musl**-бинарник (`aarch64-unknown-linux-musl` и
  другие цели), собран из официального SDK соответствующего выпуска.
- **Панель LuCI** (со встроенным русским) — `architecture all`: одинакова для всех
  архитектур и не зависит от ABI.
- Единственная сборко-зависимая зависимость — `kmod-tun`; она подтягивается из
  **собственных** репозиториев устройства и должна соответствовать работающему ядру.
- Прямые пакеты собраны из SDK **OpenWrt 25.12.5** (`r33051-f5dae5ece4`) — выпуск 25.12,
  **OpenWrt 24.10.8** (`r29233-443ec4032a`) — выпуск 24.10; SNAPSHOT — ревизия
  **r36953-0ab51fb9c1**.
- Пакеты не подписаны ключом репозитория OpenWrt — поэтому при установке `apk` нужен
  `--allow-untrusted`.

## Статус проверки

| Выпуск | Архитектуры | Что подтверждено |
|---|---|---|
| **25.12.x** | `aarch64_cortex-a53`, `aarch64_generic`, `x86_64`, `arm_cortex-a7_neon-vfpv4` | живая работа на устройстве — только `aarch64_cortex-a53` (mediatek/filogic), включая передачу данных |
| **24.10.x** | те же четыре | состав артефактов, фиды зависимостей и сухие прогоны менеджера пакетов; **на устройстве не проверялось** |
| **SNAPSHOT** | `aarch64_cortex-a53` | то же, для зафиксированной ревизии `r36953-0ab51fb9c1`; **на устройстве не проверялось** |

«Стабильный выпуск» **не означает**, что все архитектуры и выпуски проверены на живых
устройствах: для 24.10, SNAPSHOT, `x86_64`, `aarch64_generic` и `arm_cortex-a7_neon-vfpv4`
подтверждены состав артефактов, фиды зависимостей и сухие прогоны, но испытаний на
физических устройствах не было.

SNAPSHOT — rolling-сборка, поэтому «совместимость со всеми SNAPSHOT» не обещается:
гарантируется проверяемая совместимость конкретной зафиксированной ревизии. Установщик
проверяет сборку на месте и останавливается при несовпадении ядра и `kmod-tun`.

Минимальные требования к памяти и список проверенных моделей роутеров **не заявляются**.

## Известные ограничения

- Только **interface-only**: без пользовательского прокси, привязанного к `csqtt0`, весь
  трафик остаётся вне туннеля.
- `auto_js` / `auto_api` требуют действующего VK-токена с доступом к звонкам; токен имеет
  срок жизни.
- Пакеты не подписаны ключом репозитория OpenWrt — установка `apk` с `--allow-untrusted`.
- Совместимость с Podkop/Forkop подтверждена анализом исходников, с ZeroBlock 0.8.5-r101 —
  анализом фактических пакетов (выход через интерфейс есть:
  `output_network_interface` / `bind_interface`); **на устройстве эта связка не
  запускалась**, клиенты перехватывают системный DNS и конфликтуют между собой (см.
  [совместимость](compatibility.md)).
- SNAPSHOT — rolling-сборка: совместимость гарантируется только для указанной ревизии.

## Внутренние проверки

Логика клиента покрыта автотестами на стороне разработки:

| Набор | Что проверяет |
|---|---|
| Rust-ядро | сборка, `fmt`, `clippy`, модульные тесты ядра |
| Служба | интеграция CSQTT с OpenWrt (init, UCI, статусы) |
| Панель LuCI | страницы, состояния, переводы (согласованность `pot`/`po`/JSON) |
| Установщик | определение выпуска/архитектуры, манифест, контрольные суммы, зависимости |
| Удаление | состав удаляемых файлов, обработка ошибок, сохранение конфигурации |
| Миграция | перенос и сохранение конфигурации между версиями |

Часть наборов выполняется в изолированной среде **без реального роутера** и **не заменяет**
проверку на устройстве.
