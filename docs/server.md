# Свой сервер CSQTT на VPS

Установка серверной части CSQTT на арендованный сервер (VPS) — без Android-телефона.

> **Все команды этой страницы выполняются на VPS по SSH.** Для роутера и для WSL они
> не подходят; команды для роутера — в README и в документе
> [«Установка на роутер»](install.md).

## Что понадобится

- VPS с **Ubuntu** или **Debian**, процессор **x86-64**, доступ **root** (администратор).
- **systemd** и **TUN** — установщик проверит их наличие.
- Свободный порт **80/TCP** — для получения сертификата Let's Encrypt (см. «Важно знать»).

## Установка

**Шаг 1. Подключитесь к серверу** (на компьютере или прямо в VPS-терминале). Вместо
`<АДРЕС_VPS>` укажите IP вашего сервера:

```sh
ssh root@<АДРЕС_VPS>
```

**Шаг 2. Скачайте загрузчик и запустите установку** (на VPS). Серверный установщик — это
`install-server.sh`, запускаемый им `server/serverctl.py` и зафиксированный
`server/source-lock.json`. Загрузчик `install-server-online.sh` проверяет, что есть
`curl`/`wget` и `python3`, скачивает эти три файла в созданный им временный каталог, запускает
штатный установщик с переданными аргументами и убирает за собой. `--work-dir` задаёт рабочий
каталог:

```sh
curl -fsSLo /tmp/csqtt-server.sh https://raw.githubusercontent.com/starkugz/csqtt-openwrt/main/install-server-online.sh \
  && sh /tmp/csqtt-server.sh --work-dir /root/csqtt-server-work/setup
```

**Шаг 3. Ответьте на вопросы установщика:**

- **Порты.** Нажмите Enter, чтобы оставить предложенные, или введите свои. По умолчанию
  используются `46000/UDP` для подключения и `46002/TCP` для панели. Если порт занят,
  установщик предложит выбрать другой.
- **`device_id`.** Идентификатор из настроек уже настроенного клиента CSQTT. Сохраните
  прежнее значение; при вводе символы не отображаются.
- **Подтверждение.** Введите `yes`, чтобы начать установку.

**Шаг 4. Дождитесь завершения.** В терминале появятся **адрес панели, логин и пароль**, а
также данные для подключения роутера. Пароли создаются автоматически. Откройте адрес
панели в браузере и войдите с полученными данными.

Данные доступа также сохраняются на сервере в защищённом файле
`/root/csqtt-server-work/setup/access-<дата>-<время>.txt`. Не публикуйте этот файл. Без
интерактивного терминала данные записываются только в файл.

**Если сервер уже установлен,** повторный запуск сообщит об этом и ничего не изменит. При
обнаружении неполной установки он остановится с пояснением.

## Удаление

Подключитесь к VPS по SSH и выполните команду ниже (на VPS). Она покажет, что будет
удалено, и запросит подтверждение.

> **Сервер и панель будут остановлены, подключение через этот сервер перестанет
> работать.**

```sh
curl -fsSLo /tmp/csqtt-server.sh https://raw.githubusercontent.com/starkugz/csqtt-openwrt/main/install-server-online.sh \
  && sh /tmp/csqtt-server.sh uninstall --work-dir /root/csqtt-server-work/setup
```

По умолчанию настройки и данные доступа сохраняются, создаётся защищённая резервная
копия. Повторный запуск удаления сообщит, если CSQTT уже отсутствует.

Если обнаружены файлы, которые могут использовать другие программы, удаление остановится
до изменений. Не удаляйте эти файлы вручную ради обхода проверки.

## Повторная установка и удаление данных

**Установить заново с прежними настройками.** Выполните команду установки выше. Сохраните
каталог `/root/csqtt-server-work/setup`: в нём находится файл `credentials.json` с данными
доступа.

Если прежнего каталога нет, добавьте к концу команды установки
`--credentials-file "/путь/credentials.json"`, указав существующий файл. Без него
установщик остановится: новые пароли вместо прежних автоматически не создаются. Для
скрытого ввода существующих данных вручную предусмотрен параметр `--manual-credentials`.

**Удалить настройки и данные доступа.** Добавьте `--purge` к концу команды удаления и
подтвердите действие. Будут удалены `/etc/csqtt`, а в указанном рабочем каталоге —
`credentials.json`, файлы `access-*.txt` и каталог `prepared/`. Ранее созданные резервные
копии, журналы, файл `server-addr` и скачанный APK останутся. Новая резервная копия в этом
режиме создаётся только при указании `--backup-dir`. Сам рабочий каталог целиком не
удаляется.

## Важно знать

- **Сертификат для панели.** Для защищённого входа в панель установщик пытается получить
  сертификат Let's Encrypt. Для этого нужен свободный порт `80/TCP`. Если получить
  сертификат не удалось, браузер может показать предупреждение. До ввода пароля проверьте
  адрес панели и причину предупреждения.
- **Совместимость с 3x-ui, Xray и nginx.** Совместная работа CSQTT с указанными
  компонентами на одном VPS проверена, включая передачу данных через туннель.
